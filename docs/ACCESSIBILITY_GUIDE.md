## 1. 인식의 용이성

### 1.1 대체 텍스트 ✅

**요구사항**: 모든 이미지, 아이콘, 버튼에 대체 텍스트 제공

**iOS 구현**

```swift
// Interface Builder
// Accessibility > Enabled: ON
// Label: "홈으로 이동"

// 코드
button.isAccessibilityElement = true
button.accessibilityLabel = "홈으로 이동"
button.accessibilityHint = "메인 화면으로 돌아갑니다"
```

**Android 구현**

```xml
<!-- XML -->
<ImageButton
    android:contentDescription="홈으로 이동"
    android:src="@drawable/home_icon"/>
```

**React Native 구현**

```tsx
<Image
  source={require('./home.png')}
  accessible={true}
  accessibilityLabel="홈으로 이동"
  accessibilityHint="메인 화면으로 돌아갑니다"
/>
```

**체크리스트**

- [ ] 모든 이미지에 의미 전달하는 대체 텍스트 제공
- [ ] 장식용 이미지는 대체 텍스트 생략 또는 빈값
- [ ] "버튼", "이미지" 등 중복 단어 제거 (스크린리더가 자동 제공)
- [ ] 짧고 명확하게 작성 (15단어 이내 권장)

---

### 1.2 자막, 수화 등의 제공 ✅

**요구사항**: 동영상/음성 콘텐츠에 자막, 원고, 수화 제공

**체크리스트**

- [ ] 모든 영상에 자막 제공
- [ ] 자막은 영상과 동기화
- [ ] 화면 내 문자 정보는 음성으로도 제공
- [ ] 라이브 콘텐츠는 실시간 자막 제공

---

### 1.3 색에 무관한 인식 ✅

**요구사항**: 색상만으로 정보를 구분하지 않음

**잘못된 예**

- 빨간색 = 필수입력, 파란색 = 선택입력

**올바른 예**

- 빨간색 + "*" 표시 = 필수입력
- 체크박스 선택 = 체크 아이콘 + 색상 변화

**체크리스트**

- [ ] 색상 + 텍스트/기호/패턴 조합 사용
- [ ] 그래프는 범례에 구체적 수치 포함
- [ ] 선택/비선택 상태를 아이콘으로도 구분
- [ ] 색각이상 시뮬레이터로 테스트

---

### 1.4 명도 대비 ✅

**요구사항**: 전경색과 배경색 명도 대비 3:1 이상

**권장 비율**

- 일반 텍스트: 4.5:1 이상
- UI 컴포넌트: 3:1 이상

**체크리스트**

- [ ] 텍스트와 배경 대비 충분
- [ ] 버튼, 입력창 테두리 대비 충분
- [ ] 명도 대비 측정 도구로 검증
- [ ] 다크모드 지원 시 각각 테스트

---

### 1.5 명확한 지시 사항 ✅

**요구사항**: 모양, 크기, 위치, 색, 소리에만 의존하지 않음

**잘못된 예**

- "왼쪽 버튼을 누르세요"
- "빨간색 버튼을 클릭하세요"

**올바른 예**

- "취소 버튼을 누르세요"
- "확인 버튼(녹색 버튼)을 클릭하세요"

**체크리스트**

- [ ] 버튼 명칭으로 안내
- [ ] 위치 정보는 보조 정보로만 사용
- [ ] 음성 알림은 시각 정보와 병행

---

### 1.6 알림 기능 ✅

**요구사항**: 시각, 청각, 촉각 등 다양한 방법으로 알림 제공

**체크리스트**

- [ ] 푸시 알림: 소리 + 진동 + 화면 표시
- [ ] 사용자가 알림 방식 선택 가능
- [ ] 중요 알림은 다중 감각 활용

## 2. 운용의 용이성

### 2.1 초점 ✅

**요구사항**: 모든 UI 컴포넌트에 초점 적용, 논리적 순서로 이동

**iOS 구현**

```swift
// 초점 순서 제어
view.accessibilityElements = [button1, button2, textField]

// 초점 활성화
customView.isAccessibilityElement = true
```

**Android 구현**

```xml
<TextView
    android:focusable="true"
    android:nextFocusDown="@id/next_item"/>
```

**React Native 구현**

```tsx
<View
  accessible={true}
  accessibilityElementsHidden={false}
  importantForAccessibility="auto"
>
  <TouchableOpacity
    accessible={true}
    accessibilityRole="button"
    accessibilityLabel="확인"
    accessibilityState={{ selected: false }}
  />
</View>
```

**체크리스트**

- [ ] 모든 버튼, 링크, 입력창에 초점 적용
- [ ] 초점 이동 순서가 논리적 (좌→우, 상→하)
- [ ] 숨겨진 요소는 초점에서 제외
- [ ] 모달/레이어 팝업 시 해당 영역에만 초점
- [ ] 초점 표시가 명확히 보임

---

### 2.2 누르기 동작 지원 ✅

**요구사항**: 복잡한 제스처도 단순 탭으로 대체 가능

**체크리스트**

- [ ] 핀치 줌 → +/- 버튼 제공
- [ ] 스와이프 → 이전/다음 버튼 제공
- [ ] 드래그 앤 드롭 → 선택 + 이동 버튼
- [ ] 멀티터치 → 단일 터치 대체 수단
- [ ] VoiceOver/TalkBack 제스처 지원

---

### 2.3 응답 시간 조절 ✅

**요구사항**: 시간 제한 있는 콘텐츠는 연장/조절 가능

**체크리스트**

- [ ] 세션 만료 전 최소 20초 전 알림
- [ ] 시간 연장 옵션 제공
- [ ] 보안/게임 등 불가피한 경우 사전 안내
- [ ] 인증번호 재전송 기능 제공

---

### 2.4 정지 기능 제공 ✅

**요구사항**: 자동 변경 콘텐츠 제어 가능

**체크리스트**

- [ ] 배너 슬라이드: 정지/재생 버튼
- [ ] 자동 스크롤: 일시정지 기능
- [ ] 이전/다음 버튼 제공
- [ ] 현재 위치 표시 (1/5 등)

---

### 2.5 컨트롤 크기와 간격 ✅

**요구사항**: 터치 영역 최소 9mm × 9mm (약 48dp)

**체크리스트**

- [ ] 버튼 최소 크기: 가로/세로 각 9mm
- [ ] 버튼 간 충분한 간격 확보
- [ ] 터치 영역이 시각적 영역보다 크게
- [ ] 작은 버튼은 주변 여백 확대

## 3. 이해의 용이성

### 3.1 입력 도움 ✅

**요구사항**: 입력 오류 방지 및 정정 방법 제공

**Android 구현**

```xml
<EditText
    android:hint="이메일 주소를 입력하세요"
    android:contentDescription="이메일 입력"/>
```

**React Native 구현**

```tsx
<TextInput
  placeholder="이메일 주소를 입력하세요"
  accessibilityLabel="이메일 입력"
  accessibilityHint="이메일 형식으로 입력해주세요"
/>
```

**체크리스트**

- [ ] 모든 입력창에 용도 표시 (placeholder/label)
- [ ] 입력 형식 안내 (예: 2024-01-01)
- [ ] 오류 발생 시 구체적 안내
- [ ] 오류 위치로 초점 자동 이동
- [ ] 필수/선택 입력 명확히 구분

---

### 3.2 사용자 인터페이스의 일관성 ✅

**요구사항**: 동일 기능은 동일한 UI로 제공

**체크리스트**

- [ ] 뒤로가기 버튼 위치 일관성
- [ ] 확인/취소 버튼 순서 일관성
- [ ] 같은 기능은 같은 아이콘 사용
- [ ] 탭 메뉴 구조 일관성

---

### 3.3 깜빡거림 사용 제한 ✅

**요구사항**: 초당 3~50회 깜빡임 금지

**체크리스트**

- [ ] 광과민성 발작 유발 콘텐츠 회피
- [ ] 불가피한 경우 사전 경고
- [ ] 건너뛰기 옵션 제공

---

### 3.4 자동재생 금지 ✅

**요구사항**: 3초 이상 배경음 자동 재생 금지

**체크리스트**

- [ ] 동영상/음악은 사용자 선택 후 재생
- [ ] 자동 재생 시 정지 버튼 제공
- [ ] 앱 내 음량 독립 조절 가능

---

### 3.5 예측 가능성 ✅

**요구사항**: 예상치 못한 화면 전환/이벤트 사전 안내

**체크리스트**

- [ ] 외부 앱/브라우저 이동 전 안내
- [ ] 팝업 발생 전 예측 가능하게
- [ ] 화면 전환 시 명확한 레이블
- [ ] "새 창에서 열림" 등 명시

## 4. 견고성

### 4.1 폰트 관련 기능 ✅

**요구사항**: 시스템 폰트 크기 설정 반영

**iOS 구현**

```swift
label.font = UIFont.preferredFont(forTextStyle: .body)
label.adjustsFontForContentSizeCategory = true
```

**Android 구현**

```xml
<TextView
    android:textSize="16sp"
    android:textAppearance="@style/TextAppearance.AppCompat.Body1"/>
```

**React Native 구현**

```tsx
// allowFontScaling={true} (기본값)
<Text style={styles.text} allowFontScaling={true}>
  내용
</Text>
```

**체크리스트**

- [ ] 시스템 폰트 크기 설정 반영
- [ ] 텍스트 이미지 대신 실제 텍스트 사용
- [ ] 200% 확대 시에도 레이아웃 유지
- [ ] 범용 폰트 사용
